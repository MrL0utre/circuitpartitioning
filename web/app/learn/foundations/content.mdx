# Turn a circuit into a partitioning question

Circuit partitioning assigns circuit elements to a finite set of parts while satisfying constraints and optimizing one or more objectives. That compact sentence hides the choices that make published results comparable—or incompatible.

## 1. The problem is a family of models

A partitioning instance usually contains a representation of connectivity, a target set of parts or devices, resource demands, capacity limits, and a cost model. A solution maps every eligible element to exactly one part. Whether that solution is useful depends on the semantics attached to those objects.

For a vertex set $V$ and a set of parts $K$, a partition can be written as a total assignment $P: V \rightarrow K$. The simplest feasibility condition requires each vertex to appear exactly once. Practical models also constrain resource load, legal placement, clocking, or timing.

<Note title="Keep the physical and mathematical layers separate">

A netlist, a graph, and a hypergraph may describe related connectivity, but they do not necessarily preserve the same fan-out, timing, or placement information. The model profile must travel with the result.

</Note>

## 3. Feasibility first, objectives second

For part $k$, let $u_k(P)$ be its resource use and $C_k$ its capacity. A candidate is feasible only when $u_k(P) \leq C_k$ for every constrained resource and part. Objective values should not hide an infeasible assignment.

The initial scientific convention profile records three useful objective families:

### Cut objective

$$
f_c(P) = \sum_{e \in E} w_e\, \mathbf{1}\!\left[\left|\{P(v): v \in e\}\right| > 1\right]
$$

$f_c$ charges a weighted hyperarc when its incident vertices span more than one part. Alternative cut definitions must use distinct metric identifiers.

### Topology-aware communication objective

$$
f_{\lambda}(P, T) = \sum_{e \in E} w_e\, d_T\!\left(P(s_e), \{P(v):v\in e\}\right)
$$

$f_{\lambda}$ combines the partition with a target topology $T$. Its interpretation depends on the declared routing or distance rule; it is not interchangeable with an unweighted cut.

### Timing or path objective

$$
f_p(P) = \max_{\pi \in \Pi} \sum_{v \in \pi} d_v + \sum_{(u,v) \in \pi} d_{uv}(P)
$$

$f_p$ evaluates the longest relevant path under declared vertex and connection delays. The path set $\Pi$ and the treatment of state boundaries belong to the model profile.
